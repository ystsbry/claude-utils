# ユーザージャーニー・ストーリーテリング検証

ユースケースが「単一機能の正常系」を見るのに対し、本スキルは **複数機能を跨ぐ中長期的な体験** を物語として検証します。

## 検証の主な観点

- **体験の連続性**: 機能と機能の間で文脈・状態が引き継がれるか
- **機能間整合性**: ある機能で作ったデータが別機能で違和感なく使えるか
- **離脱ポイント**: 何かが面倒・不可解で諦める箇所はどこか
- **感情曲線**: 期待・不安・喜び・苛立ちの動きが自然か、谷を埋める手当てがあるか
- **オンボーディング・初回体験**: ユーザーが価値にたどり着くまでの摩擦
- **長期的な再訪・継続**: 状態の保存・思い出させる仕組み・通知
- **ユビキタス言語**: ユーザーが実際に使う言葉と、UI／設計上の言葉が一致しているか

---

## ステップ1: 入力を読み込む

セッション名がユーザーから渡されていない場合は確認してください。

以下を読み込みます：

- 必須: `~/.claude-utils/session/<session-name>/story-telling-input.md`
- 補助: `~/.claude-utils/session/<session-name>/design-doc.md`（あれば）
- 補助: 関連するコードベース、UI

design-doc がある場合は、想定アクター・想定業務・スコープを必ず確認します。

---

## ステップ2: ペルソナとジャーニーを複数本生成する

### ペルソナの設定

まず **ペルソナ** を 2〜4 体生成します（既に design-doc にある場合は引き継ぐ）。各ペルソナについて簡潔に：

- 背景（職業・スキル・プロダクトとの関わり）
- 動機（何を達成したい）
- 制約（時間・デバイス・前提知識・心理的状態）

### ジャーニーの生成

各ペルソナについて、**網羅性を重視** して以下の時間軸でジャーニーを生成：

- **初回体験**: サインアップ〜初の成功体験（Aha moment）
- **典型的な利用日**: 中核機能を一通り使う 1日
- **エッジ的な利用**: 通常から外れた使い方、複数アカウント、組織での共有、デバイス間移動
- **トラブルからの回復**: ミス・気が変わった・取り消したい・データを戻したい
- **長期利用**: 数週〜数ヶ月、状態が育ってきたとき
- **離脱・復帰**: 一度去ったユーザーが戻ってくるとき

最低でも 1ペルソナにつき 2 ジャーニー、合計 4〜8 本を目安に。**まずペルソナとジャーニーのタイトル一覧をユーザーに提示** し、過不足を確認してから本文に進むことを推奨します。

各ジャーニーは以下の形式で記述してください：

```
ジャーニー <N>: <ペルソナ> × <時間軸>

- ペルソナ: <名前と背景>
- 期間: <分単位 / 日単位 / 月単位>
- 物語:
  時刻 T0: <状況・行動・感情>
  時刻 T1: <状況・行動・感情>
- 体験のゴール: <ユーザーが何を達成したいか>
- 感情曲線: <期待 → 不安 → 喜び … のような流れを言葉で>
```

---

## ステップ3: 各ジャーニーをアーキテクチャに照らす

各ジャーニーで、ユーザーの行動・期待・状態が **どのコンポーネントによって支えられるか** をマッピングします。検証ポイント：

- ある時刻で必要な情報・状態が **保持されているか**（誰が、どこに、どれくらいの期間）
- 機能間の **遷移** が設計に存在するか（リンク、通知、レコメンド、状態の引き継ぎ）
- ユーザーの **再訪時の文脈復元** は設計上自然にできるか（中断箇所からの再開、過去の入力の保持）
- **言葉の一致**: UI ラベル・通知文言・エラーメッセージと、設計上の用語のズレ
- **感情曲線の谷** に対応する設計上の手当てがあるか（待ち時間の埋め方、不安解消、再開支援、進捗表示）
- **長期的な状態の育ち** をデータモデルが許容しているか（初期は2件、半年後に1万件のとき UI もデータも耐えるか）

## ステップ5: フィードバックと改善

- ペルソナ・ジャーニーの過不足を確認
- 特定のペルソナや時間軸を追加・深掘りしたい要望があれば対応

---

## 書き方の注意点

- **物語を「機能の使い方」で終わらせない**: ユーザーの状況・気持ち・周辺の文脈（時間帯、デバイス、隣にいる人）まで描くと、機能間の文脈引き継ぎや感情曲線の谷が見えやすい
- **時間軸を意識的にずらす**: 1分・1時間・1日・1週間・1ヶ月・半年。設計が暗黙に前提にしている時間軸を炙り出す
- **「機能はあるが体験が成立しない」を明示する**: 個別のユースケースは成立しても、ジャーニーで繋ぐと破綻するケースを言語化する
